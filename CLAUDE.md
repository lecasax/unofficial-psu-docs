# Unofficial PSU Docs

Fan-made, improved versions of **selected** pages from the Phantasy Star
Universe Clementine wiki (https://psu-clementine.com/wiki/). Not a full copy
of the wiki: improve a few pages at a time.

The user writes in Portuguese (pt-BR). Site content is in English, like the
source wiki and the item names.

## Stack

- SvelteKit 3 (Svelte 5 runes, TypeScript) with `adapter-static`: every page
  is prerendered to static HTML. No backend.
- UI: Material Design 3 through `m3-svelte`. Use its components and its
  `--m3c-*` color tokens, `--m3-shape-*` and `@apply --m3-<type-style>`
  typography instead of hard-coded colors and font sizes. MD3 has no data
  table component, so tables are our own, built on those tokens.
- m3-svelte CSS uses `@mixin`/`@function`, expanded at build time by
  `vite-plugin-functions-mixins`. That plugin declares Vite 7 only, so
  `package.json` has an `overrides` entry to use it with Vite 8; it works
  (checked: no `@apply` left in the built CSS). Remove the override once the
  plugin supports Vite 8.
- Theme: `src/theme.css` is generated by `npm run theme -- "#hex"` from one
  seed color (currently `#4cc3ff`, Fidelity scheme variant). Do not edit it
  by hand.
- Deploy: `.github/workflows/deploy.yml` builds with `BASE_PATH=/<repo name>`
  and publishes `build/` to GitHub Pages (Pages source must be "GitHub
  Actions"). Internal links must go through `resolve()` from `$app/paths`
  so they keep the base path.
- `npm run check` reports "Unknown at rule @apply" warnings: expected, the
  CSS checker does not know mixins.

## First page: Ultimate Drop Table

Source: https://psu-clementine.com/wiki/Ultimate_Drop_Table

The wiki table has the columns Weapon | Enemy Drop | Mission Drop | Area Drops,
grouped by weapon type (Swords, Knuckles, Spears, Double Sabers, Axes,
Handguns, Crossbows, Cards, Machineguns, Rods, Wands, TCSMs, maybe more).

Planned improvements:
1. Views by mission, enemy and area, generated from the same data.
2. Weapon attributes (stars, element, classes, required level, icon).
3. Source context: boss/rare/common enemy, where the enemy spawns,
   drop rate (only if the server team provides it; never invent it).
4. Cleanup: `x` placeholders become "—", explain the `/U+` suffix and
   Mission vs Area columns, consistent names (e.g. `YG-01Z BUG` /
   `YG01U BUGGES` / `YG-01K BUGGE`), no links to missing wiki pages.
5. Search, filters, sorting, mobile-friendly cards.
6. "Last verified" date, data source, and a way to report drops
   (GitHub issues).

Scope and filters (decided with the user, 2026-10-30):
- Item types: every weapon type, plus the units (Head/Arm/Body) and Line
  Shields listed at the end of the drop table. That unit list is short and
  incomplete (21 of ~290 units; no Extra units); show unknown drops as
  unknown, never guess.
- Each item name opens a rich tooltip with the item's picture on top, as
  the wiki's own hover preview does, and its properties below (stats,
  stars, manufacturer, element, requirement, special effect...), not just
  a description. The user asked for the picture on 2026-10-30. Weapon
  pictures are the wiki's files named after the item id
  (`<id>.png`, hashed MediaWiki folder); the page links to them and never
  copies them. Units and Line Shields have no picture on the wiki.
- The user found the first design amateurish ("horrorosa") and wants a
  professional, unmistakably MD3 product look, in dark and light themes.
- Filters: equipment type; class ("Type" on the wiki: 16 of them, from the
  "Usable Weapons by Type" matrix on the Weapons page, ranks S/A/B/C;
  Master Types use only S-rank weapons and Line Shields); planet (Parum,
  Neudaiz, Moatoob, GUARDIANS/space), mapped from the drop areas;
  stars/rank (1-15★, C/B/A/S) as the "level" filter, since items have stat
  requirements, not level requirements; race (Human, Newman, CAST, Beast),
  if the data has race restrictions (none seen on the pages read so far).

First version built 2026-10-30: `/ultimate-drop-table`
(`src/routes/ultimate-drop-table/`, components in `src/lib/drop-table/`).
- A weapon's classes are the matrix (weapon rank <= the class's rank for
  that weapon type) combined with the weapon's own Cargo `class` list.
  Master types also need an S-rank weapon, except Handguns for Fighmaster
  and Masterforce (C rank). Each Master type's wiki page states this.
  Gunmaster has no Handguns, so Heaven Striker/U+ (a Handgun) is out.
  Checked 2026-10-30: the matrix matches all 16 class pages, and every
  type uses S-rank Line Shields, so shields and units suit every type.
- The race filter appears by itself only if some weapon has fewer than four
  races in the data. Units and Line Shields have no race data.
- Missions get their planet from the Missions and Rare Missions pages;
  enemies from Enemies, Rare Enemies and Bosses; areas from a fixed map in
  the build script. Anything not found there has no planet; do not guess.

Redesign chosen by the user on 2026-10-31: the MD3 list-detail layout
("prototype B"). Filters in a left rail, results in the middle, and the
item's picture, properties and drops in a right panel.
- 840 px and wider: resting the mouse on a row (150 ms, `hover-intent.ts`),
  clicking it or focusing it shows the item in the right panel. There is no
  floating card at these widths; the user asked for the panel instead.
- Narrower, with a mouse: a preview card (`HoverCard.svelte`), and a click
  opens a dialog. Phones: a full-screen sheet (`ItemSheet.svelte`) that the
  system Back closes.
- No native `<select>` anywhere. In the user's Chrome the native list opened
  far from the field. Dropdowns are MD3 menus (`src/lib/ui/MenuButton.svelte`);
  long lists such as Type use the searchable one (`SearchMenu.svelte`).
- Shared UI is in `src/lib/ui/` (app bar, menus, sheet, theme menu). Page
  logic and data helpers are in `src/lib/drop-table/model.ts`. Search,
  filters, sort and the shown item are kept in the URL query.
- The theme follows the system; the toggle saves `psu-docs-theme` in
  localStorage, and an inline script in `src/app.html` applies it before
  the first paint.

## Data source notes

- Direct downloads from psu-clementine.com (curl) return 403. Do not try to
  get around the block.
- Large pages fetched with WebFetch come back partly summarized, so they
  are not reliable for full data extraction.
- The best source is the wiki text of the pages, saved by the user from the
  browser into `data/raw/`: "View source" for one page, or
  https://psu-clementine.com/wiki/Special:Export (paste titles, "Include
  only the current revision", "Include templates", "Save as file") for many
  pages at once as one XML file.
- Weapon stats live only in the wiki's Cargo tables (Weapons, Items, Drops),
  saved as JSON from Special:CargoExport into `data/raw/cargo/`. The export
  returns at most 512 rows per request, so `data/cargo-download.html` lists
  one link per page (`order_by=_ID` with `offset`). File names do not
  matter; the build script finds each table by its fields.
- The export turns numeric-looking hex item ids into numbers ("01020403" ->
  1020403, "010E0103" -> 1e104). Join ids only through `idKey()` in the
  build script.
- `npm run data` (`scripts/build-data.ts`) builds
  `src/lib/drop-table/data.json` from `data/raw/` and prints every name it
  could not match. Fix those in the script, never by guessing data.
- Weapon icons and images are SEGA's and hosted on the wiki. Ask the wiki
  team before copying them.

## Code notes

- `#lib/...` imports of `.ts` files need the `.js` extension
  (`'#lib/site.js'`); `.svelte` and `.json` files use their own.
